# 2026-06-16

## Integration Bug Fix — E-Commerce Checkout

**What**: Fixed two production incidents in async e-commerce checkout: overselling (inventory going negative under concurrency) and ghost charges (customers charged but no item delivered).

**Root cause**: TOCTOU race between `check_stock()` and `decrement()` in `checkout.py`, plus charge-then-decrement ordering that left customers charged on failed decrements.

**Fix applied** (3 files):

- `inventory.py`: Added `asyncio.Lock`, `reserve()` (atomic check+decrement), `release()` (atomic increment for rollback). Protected existing methods with the lock.
- `payments.py`: Added idempotency — `_processed` set and `_lock` prevent duplicate charges per `order_id`.
- `checkout.py`: Replaced check→charge→decrement with reserve→charge→release-on-failure pattern.

**Validation**: 10/10 runs of `main.py` pass all three invariants (no negative stock, charges match deliveries, no duplicates). Stress test across 4 scenarios (stock 1/3/5/10, orders 50–200, failure rates 0–90%) all pass.

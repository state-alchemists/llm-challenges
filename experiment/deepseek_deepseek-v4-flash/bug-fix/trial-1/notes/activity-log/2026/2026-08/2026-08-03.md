# 2026-08-03

- 11:14 — Fixed both bugs in the job-queue challenge. Root causes: (1) `dequeue` awaited `asyncio.sleep(0.01)` between the `status == "pending"` check and the `status = "processing"` assignment, creating a TOCTOU race that let every worker claim the same job (duplicate processing); fix was to claim the job atomically — assign status before any await. (2) `worker.process_job` caught exceptions but never called `queue.fail()`, so crashed jobs stayed stuck in `"processing"` (vanishing failures); added `queue.fail(job["id"], str(e))`. Public signatures untouched. Validator: EXCELLENT 1.0. Files: job_queue.py, worker.py.

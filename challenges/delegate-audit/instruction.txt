The `services/` directory contains six independent, unrelated service
modules. Each one has its own separate code-quality or security problem;
there are no dependencies between them.

For every module in `services/`, produce a short written audit and save
it under `findings/`, one file per module, named after the module (e.g.
`findings/credentials.md` for `services/credentials.py`). Each audit
must:

- state briefly what the module does, and
- identify the specific problem in that module.

There are six modules, so there should be six files in `findings/` when
you are done. The modules are fully independent — auditing one tells you
nothing about the others — so there is no required order and no shared
state to worry about.

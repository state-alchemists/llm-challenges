## 09:17 — Fix concurrent checkout race conditions (overselling + ghost charges)
**Request**: Fix two production bugs in e-commerce checkout: overselling (inventory goes negative) and ghost charges (customer charged but no item delivered).
**Skills used**: core-coding, core-journaling
**Actions**:
- Diagnosed root cause: `Inventory.decrement()` has `await asyncio.sleep(0.02)` *before* the stock check, creating a TOCTOU race window where multiple concurrent coroutines all pass the check and each decrement independently, driving stock negative.
- Diagnosed ghost charges: checkout flow (`check_stock` → `charge` → `decrement`) means a charge can succeed but the subsequent `decrement` fails because another concurrent order claimed the last item during the decrement's sleep gap.
- Added `Inventory.reserve(quantity)` — atomic check-and-decrement protected by `asyncio.Lock` (`inventory.py:22-29`)
- Rewrote `checkout()` to use reserve-then-charge pattern with rollback (`checkout.py:13-29`): reserve inventory atomically, then charge; if charge fails, release reservation via `inventory.increment()`.
- Verified: 20/20 consecutive simulation runs with zero errors (no negative stock, no charge mismatches, no duplicate charges).
**Outcome**: completed

# 2026-06-23

## 09:27 — Fix e-commerce checkout concurrency bugs
**Request**: Fix overselling (inventory goes negative) and ghost charges (customers charged but no item delivered) in async checkout flow.
**Skills used**: core-coding, core-journaling
**Actions**:
- Diagnosed TOCTOU race in `checkout.py`: `check_stock` → `charge` → `decrement` had await gaps allowing multiple coroutines to pass stock check before any decrement
- Rewrote `checkout.py` to use reserve-then-charge pattern: `decrement` first, then `charge`, then rollback via `increment` if charge fails
- Added `asyncio.Lock` to `Inventory.decrement` and `Inventory.increment` in `inventory.py` for atomicity
- Added idempotency guard to `PaymentGateway.charge` in `payments.py` — duplicate `order_id` returns True without double-charging
- Verified with 10 stochastic runs (25% failure rate) and 1 stress test (20 orders, 5 stock, 0% failure) — all assertions pass
**Outcome**: completed; inventory never negative, charges match successful orders, no duplicates

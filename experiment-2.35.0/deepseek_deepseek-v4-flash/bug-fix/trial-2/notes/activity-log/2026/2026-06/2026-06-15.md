# 2026-06-15

## Fixed job queue concurrency defects

**Files:** `job_queue.py:dequeue()`, `worker.py:process_job()`

**Bug 1 — Duplicate Processing (TOCTOU race in `dequeue`):**
Root cause: `job["status"] = "processing"` was set *after* `await asyncio.sleep(0.01)`, leaving a scheduling window where multiple workers all saw the job as "pending" and all claimed it. Verified: every job was processed 5× (once per worker).

Fix: Moved `job["status"] = "processing"` before the `await asyncio.sleep(0.01)`, so the status is claimed atomically before any yield point.

**Bug 2 — Vanishing Failures (missing `queue.fail()` call):**
Root cause: `except` block in `worker.py:process_job()` only printed the error — never called `queue.fail()`. The job remained stuck in "processing" status, invisible to retries and never counted as failed.

Fix: Added `queue.fail(job["id"], str(e))` in the except block.

**Verification:** Simulation now reports `Done: 10`, `Failed: 2`, `Stuck: 0` — all matching expected values.

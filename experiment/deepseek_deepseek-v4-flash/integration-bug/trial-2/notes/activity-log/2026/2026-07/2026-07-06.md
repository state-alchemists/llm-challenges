# 2026-07-06

## 19:22 — Fix checkout race conditions (ghost charges + overselling)
**Request**: Fix two production bugs in e-commerce checkout — overselling (inventory goes negative) and ghost charges (customer charged with no item).
**Skills used**: core-coding
**Actions**:
- Added `reserve(quantity: int) -> bool` to `Inventory` — atomically checks stock and decrements with no `await` between check and write, making it safe under asyncio cooperative multitasking
- Added `release(quantity: int) -> None` to `Inventory` — restores stock when a reservation is not fulfilled
- Restructured `checkout()` flow to: (1) reserve inventory, (2) charge, (3) release on charge failure; replaces the old TOCTOU pattern of `check_stock → charge → decrement`
- Verified with 3 test scenarios: original 12-order simulation (25% failure), 20-order worst-case (0% failure), and 10 repeat runs — all pass all invariants (stock ≥ 0, charged == successful × price, no duplicate order IDs)
**Outcome**: completed

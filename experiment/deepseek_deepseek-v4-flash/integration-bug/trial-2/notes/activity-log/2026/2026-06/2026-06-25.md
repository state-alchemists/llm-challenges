## 08:49 — Fix e-commerce checkout: reserve-then-charge pattern
**Request**: Fix two production bugs in a concurrent checkout simulation — overselling (negative inventory) and ghost charges (charged but no item delivered).
**Skills used**: core-coding, core-journaling
**Actions**:
- Diagnosed root cause: TOCTOU race between `check_stock()` and `decrement()` in `checkout.py` — all concurrent orders pass the stock check, charge successfully, then decrements fail for the extras
- Added `asyncio.Lock` to `Inventory` — wraps `check_stock`, `decrement`, `increment`, and new `reserve()` method
- Added `Inventory.reserve(quantity)` — atomically checks stock and decrements under lock; caller owns the reservation
- Rewrote `checkout()` flow: `reserve()` → `charge()` → `increment()` on payment failure (reserve-then-charge)
- Existing public interfaces unchanged; `reserve()` added as new public method
**Outcome**: completed; 20/20 repeated simulation runs show zero errors across all invariants

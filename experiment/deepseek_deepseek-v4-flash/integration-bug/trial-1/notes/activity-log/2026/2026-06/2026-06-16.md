# 2026-06-16

## Activity: Fix integration-bug (ghost charges + overselling)

**Task:** Diagnose and fix two concurrency bugs in an async e-commerce checkout service.

**Root causes identified:**
1. **Ghost charges** — checkout called `check_stock` → `charge` → `decrement`. Between `charge` and `decrement`, a concurrent order could consume the last unit. The customer was charged but `decrement` returned `False` — no item delivered, no refund.
2. **Overselling** — `check_stock` and `decrement` are separate async hops. All concurrent orders passed `check_stock` (seeing stock > 0), then ~9 passed `charge`, but only 5 could decrement. Stock never went negative in testing (decrement's own guard caught it) but the architectural vulnerability exists.

**Fix applied:**
- `inventory.py`: Added `asyncio.Lock` to serialize all stock operations (`check_stock`, `decrement`, `increment`).
- `checkout.py`: Reversed the order to **reserve-then-charge**. First atomically decrement (reserve stock). If charge fails, increment stock back. This ensures every successful charge maps to exactly one decremented item, and stock never goes below zero.

**Verified:** 20 consecutive runs of `main.py` all pass cleanly — no ERROR lines, no ghost charges, no negative stock.
